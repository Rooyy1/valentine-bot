# Бот-консультант Валентина Михальченко

Telegram-бот на aiogram 3: приветствие → выбор категории → короткая
диагностика → персонализированная карточка тарифа → CTA "написать тренеру".

## Структура проекта

```
valentin_bot/
├── bot.py                  # точка входа, регистрация роутеров
├── config.py                # чтение .env
├── states.py                 # FSM-состояния диагностики
├── requirements.txt
├── .env.example
├── Dockerfile
├── data/
│   ├── products.py           # все тарифы: цена, состав, карточка
│   ├── texts.py               # все тексты и подписи ответов
│   └── recommend.py           # логика подбора тарифа по ответам диагностики
├── handlers/
│   ├── start.py                # /start, /menu, кнопка "В начало"
│   ├── diagnostics.py           # выбор категории + сценарии диагностики
│   ├── product.py                # карточка товара: подробнее/почему/выбрать
│   └── common.py                  # fallback на непредусмотренный ввод
└── keyboards/
    ├── main.py                    # главное меню
    ├── diagnostics.py               # клавиатуры вопросов диагностики
    └── product.py                    # клавиатуры карточки товара
```

## Тарифы (data/products.py)

| Ключ | Тариф | Цена |
|---|---|---|
| `recipes` | Книга рецептов (50+ рецептов с БЖУ) | 850 ₽ |
| `gym_training` | Персональная тренировка (~1,5 часа) | 1 500 ₽ |
| `intro` | План питания + программа тренировок | 5 000 ₽/мес |
| `online_coaching` | Онлайн-ведение (видео-разбор, поддержка 24/7) | 8 000 ₽/мес |
| `comfort` | Комфорт (4 тренировки + 8 самостоятельных) | 11 000 ₽/мес |
| `base` | База (12 тренировок) | 23 000 ₽/мес |

Чтобы поменять цену, состав или текст любого тарифа — правьте только
`data/products.py`, весь остальной код тянет данные оттуда.

## Логика диагностики (data/recommend.py)

В отличие от исходной версии, ответы пользователя **реально влияют** на
результат:

- **Тренировки** — тариф выбирается по тому, что мешает прогрессировать
  (техника → разовая тренировка, нет программы → план+программа, нет
  прогресса → онлайн-ведение). Цель тренировок используется в тексте
  обоснования.
- **Питание** — если человек просто не знает, что готовить, предлагается
  книга рецептов (850 ₽); если не понимает КБЖУ или срывается на вредное —
  предлагается план питания с поддержкой (5 000 ₽).
- **Готовая система** — один вопрос (было два дублирующих) сразу и
  однозначно определяет Комфорт/База.
- **Онлайн-ведение** — тариф всегда один, но ответы персонализируют текст
  и подсвечивают в карточке самую важную для клиента фичу.

## Запуск

```bash
cp .env.example .env
# впишите в .env свой BOT_TOKEN (и опционально TRAINER_PHOTO_ID)

python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python bot.py
```

## Запуск в Docker

```bash
docker build -t valentin-bot .
docker run -d --restart unless-stopped --env-file .env --name valentin-bot valentin-bot
```

## Продакшен-заметки

- Хранилище FSM — `MemoryStorage`: состояния сбрасываются при перезапуске
  бота. Для честного продакшена при желании можно заменить на
  `RedisStorage`, чтобы не терять прогресс диагностики при деплое.
- `handlers/common.py` подключён последним и ловит любые необработанные
  сообщения и нажатия на устаревшие кнопки — бот никогда не "зависает"
  молча и не оставляет "часики" на кнопке.
- `bot.delete_webhook(drop_pending_updates=True)` перед polling — на случай,
  если ранее был включён webhook или накопились старые апдейты.
- Логирование ошибок обработки апдейтов включено через `@dp.error()`.
