# Telegram-бот продаж для фитнес-тренера

Бот работает не как каталог с прайсом, а как мини-консультант тренера:
после `/start` рассказывает о тренере, задаёт 4 коротких диагностических
вопроса и персонально рекомендует один конкретный продукт с одной
конкретной ценой — без диапазонов и смешения услуг.

## Продукты (единый источник — `data/products.py`)

| Ключ | Продукт | Цена |
|---|---|---|
| `gym_training` | Тренировка в зале (разово) | 1 500 ₽ |
| `intro` | Введение — программа, питание, БЖУ, контроль (без личных тренировок) | 5 000 ₽ / мес |
| `online_coaching` | Полное сопровождение онлайн | 8 000 ₽ / мес |
| `intro_plus_4` | Введение + 4 тренировки в зале | 11 000 ₽ / мес ⚠️ см. примечание ниже |
| `intro_plus_12` | Введение + 12 тренировок в зале | 23 000 ₽ / мес |
| `recipes` | Электронная книга рецептов | 850 ₽ |

⚠️ **`intro_plus_4` требует подтверждения цены.** Математически
5 000 ₽ (введение) + 4 × 1 500 ₽ (тренировки) = 11 000 ₽ — так сейчас
и стоит в коде. По устной обратной связи тренера должно быть 12 000 ₽,
но это на 1 000 ₽ расходится с расчётом. Уточните у тренера и поменяйте
`"price"` у `intro_plus_4` в `data/products.py`, когда решите.

## Структура проекта

```
fitness_bot/
├── bot.py                  # точка входа, запуск polling
├── config.py                # чтение переменных окружения (.env)
├── states.py                 # FSM-состояния диагностики
├── requirements.txt
├── .env.example
├── data/
│   ├── texts.py              # все тексты (приветствие, вопросы диагностики)
│   ├── products.py           # каталог продуктов (цены, описания) + build_product_card()
│   └── recommend.py          # логика подбора продукта по ответам
├── keyboards/
│   ├── main.py                # клавиатура главного меню
│   ├── diagnostics.py         # клавиатуры 4 вопросов диагностики
│   └── product.py             # клавиатуры карточки продукта и CTA
└── handlers/
    ├── start.py                # /start, приветствие + история, возврат в меню
    ├── diagnostics.py          # шаги опроса и выдача рекомендации
    ├── product.py               # "Подробнее", "Почему подходит", CTA и т.д.
    └── common.py                 # fallback на произвольный текст
```

Хотите поменять цену, текст истории или добавить новый продукт —
правьте только файлы в `data/`, логику трогать не нужно.

## Установка и запуск

1. Убедитесь, что установлен **Python 3.10+**.

2. Создайте и активируйте виртуальное окружение:

   ```bash
   python -m venv venv
   source venv/bin/activate      # Windows: venv\Scripts\activate
   ```

3. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

4. Скопируйте `.env.example` в `.env` и укажите токен бота:

   ```bash
   cp .env.example .env
   ```

   Откройте `.env` и вставьте токен, полученный у [@BotFather](https://t.me/BotFather):

   ```
   BOT_TOKEN=123456789:AAExampleTokenFromBotFather
   ```

5. Запустите бота:

   ```bash
   python bot.py
   ```

Если всё настроено верно, в консоли появится сообщение
`Бот запущен, начинаю polling...` — можно писать боту `/start` в Telegram.

## Важно про фото тренера (file_id)

В коде используется готовый `TRAINER_PHOTO_ID` — идентификатор фотографии
в Telegram. **file_id жёстко привязан к тому боту, который изначально
принял это фото.** Если вы запускаете бота с новым токеном, этот file_id,
скорее всего, работать не будет.

Бот обрабатывает это автоматически: если фото не отправляется, приветствие
уйдёт просто текстом, без ошибки и без остановки сценария.

Чтобы фото показывалось корректно:

1. Отправьте нужную фотографию вашему боту в личные сообщения (любым
   пользователем) или самому себе через Saved Messages любым способом,
   которым бот сможет её увидеть (например, временно добавьте
   `@router.message(F.photo)` с `print(message.photo[-1].file_id)`,
   отправьте фото и посмотрите новый `file_id` в консоли).
2. Подставьте новый `file_id` в `.env` в переменную `TRAINER_PHOTO_ID`.

## Как устроена логика продаж

1. `/start` → фото + продающая история тренера → 4 кнопки-категории.
2. Выбор категории → короткий опрос: цель → проблема → формат помощи →
   бюджет (все шаги реализованы через FSM в `states.py`).
3. По ответам `data/recommend.py` подбирает один из 6 продуктов и
   формулирует персональную причину, почему он подходит.
4. Карточка продукта с кнопками:
   - «Подробнее» — полное описание;
   - «Почему мне это подходит» — персональное обоснование;
   - «Выбрать этот вариант» — переход к финальному CTA;
   - «Посмотреть другие варианты» — список всех 6 продуктов;
   - «Задать вопрос тренеру» — тоже ведёт к финальному CTA.
5. Финальный CTA — кнопка-ссылка «Написать тренеру и оформить», которая
   открывает диалог с тренером в Telegram (юзернейм задаётся в `.env`).

Оплата, CRM и админка сознательно не подключены — бот доводит
пользователя до понятного следующего шага: написать тренеру напрямую.
